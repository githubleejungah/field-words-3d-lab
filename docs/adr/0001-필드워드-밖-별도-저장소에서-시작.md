# ADR-0001: 코드 해석 게임은 필드워드 밖 별도 저장소에서 시작한다

- 상태(Status): **채택(Accepted)**
- 날짜: 2026-11-22
- 결정한 사람: 프로젝트 오너(사용자). Claude가 정리하고 추천함.

## 1. 배경 (Context)

- 필드워드에 "코드 가려 보기" 게임을 붙이고 싶다(요구 문서 원문).
- 필드워드의 데이터 반영 · 배포는 사용자의 **다른 Claude 계정**이 맡고 있다. 두 곳에서 필드워드 저장소를 고치면 `glossary.json`과 문서가 충돌한다.
- 기획을 진행하는 지금의 Claude 계정은 강의(마지막 수업 2026-11-28)가 끝나면 사용할 수 없다. 대화 기록은 사라지므로, 결정은 파일로 남아야 한다.
- 게임은 필드워드에 없던 것(코드 실행, 3D 라이브러리 가능성, 문제 데이터)을 새로 다룬다. 필드워드 ADR-0001("외부 라이브러리 없음")과 부딪힐 수 있다.

## 2. 선택지 (Options)

| 방법 | 판단 |
|---|---|
| 필드워드 저장소에 바로 브랜치를 만들어 개발 | ❌ 다른 계정 작업과 충돌, 필드워드 규칙이 시제품에도 그대로 적용됨 |
| claude.ai 웹 프로젝트에서 기획만 | ❌ 파일 · 실행 · Git 을 다루지 못하고, 계정과 함께 사라짐 |
| **필드워드 밖 별도 폴더 · 저장소에서 기획 · 시제품 → 검증 뒤 필드워드에 넘김** | ✅ 채택 |

## 3. 결정 (Decision)

1. 게임은 `C:\Users\User\실습산출물\field-words-3d-lab` 폴더(GitHub 비공개 저장소 `githubleejungah/field-words-3d-lab`)에서 기획하고 시제품을 만든다.
2. 이 저장소는 필드워드 저장소를 고치지 않는다. 필드워드 데이터는 공개 주소에서 **읽기만** 한다.
3. 결정은 모두 이 폴더의 문서(CLAUDE.md, docs/)에 남긴다. 어느 계정이든 이 폴더를 열면 이어 갈 수 있게 한다.
4. 시제품이 검증되면 필드워드에 붙이기 위한 ADR 초안(라이브러리 · 데이터 구조)을 써서 필드워드를 맡은 계정에 넘긴다.

## 4. 결과 (Consequences)

### 좋아지는 점
- 필드워드 운영과 충돌하지 않는다.
- 계정이 바뀌어도 폴더(내 PC + GitHub)만 있으면 이어 갈 수 있다.
- 시제품에서는 필드워드 규칙에 묶이지 않고 3D 라이브러리 등을 시험해 볼 수 있다.

### 감수하는 점
- 나중에 필드워드에 옮겨 붙이는 작업이 한 번 더 필요하다.
- 필드워드 데이터 구조가 바뀌면 시제품이 읽는 부분도 맞춰야 한다.

## 5. 다시 검토할 조건
- 필드워드를 맡는 계정이 하나로 합쳐질 때
- 시제품 검증이 끝나 필드워드에 붙일 때 (새 ADR로 대체)
