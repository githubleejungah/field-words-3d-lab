# ADR-0002: 예제 코드는 브라우저의 Web Worker에서 1초 상한을 두고 실행한다

- 상태(Status): **채택(Accepted)** — 2026-11-22 설계 문서와 함께 사용자 승인
- 날짜: 2026-11-22
- 결정한 사람: Claude가 제안. 프로젝트 오너(사용자)가 승인(2026-11-22).

## 1. 배경 (Context)

- 게임의 핵심은 "가린 코드를 실제로 실행해 원래 출력과 비교"하는 것이다(요구 A5, AC-19).
- 비용 0원이라 서버에서 실행할 수 없다. 학습자 브라우저 안에서 실행해야 한다(AC-01 · 02).
- 예제가 실수로 끝나지 않으면 화면이 멈춘다. 1초가 지나면 멈춰야 한다(AC-67).
- 일부 환경에서는 문자열 코드 실행 자체가 막힐 수 있다. 그때도 학습은 이어져야 한다(AC-64).

## 2. 선택지 (Options)

| 방법 | 1초 상한 | 화면과 분리 | 외부 라이브러리 | 판단 |
|---|---|---|---|---|
| 화면 안에서 바로 실행(`new Function`) | ❌ 끝나지 않는 코드를 멈출 수 없다 | ❌ | 없음 | ❌ |
| 숨긴 iframe(격리된 작은 창)에서 실행 | △ 같은 실행 줄을 쓰면 멈추기 어렵다 | ○ | 없음 | ❌ |
| **Web Worker(화면과 따로 도는 일꾼)에서 실행, 1초 뒤 `terminate()`** | ○ 일꾼째 멈출 수 있다 | ○ 화면 · 기록에 손대지 못함 | 없음 | ✅ 채택 제안 |
| 자바스크립트 해석기 라이브러리(한 줄씩 실행) | ○ | ○ | 필요 | 보류. ① 해석 보기를 자동으로 만들 수 있어 매력 있다. 그러나 ㉠ 줄마다 붙는 쉬운 설명(`note`)은 라이브러리로도 자동으로 나오지 않아 어차피 써야 하고 ㉡ 첫 시제품은 8문제(AC-74)뿐이며 ㉢ 필드워드는 "외부 라이브러리 없음"(필드워드 ADR-0001)이라 나중에 붙일 때 부딪힌다. 그래서 장면을 문제 데이터에 미리 적는다 |

## 3. 결정 (Decision)

1. `runner.js`가 실행할 때마다 Web Worker를 새로 만든다. 일꾼 안에서 `console.log`만 바꿔 끼우고 코드를 실행해 출력 목록을 돌려준다.
2. 1초(1000ms) 안에 답이 없으면 일꾼을 멈추고 "실행이 너무 길어 멈췄어요"를 보여 준다.
3. 일꾼을 만들 수 없거나 코드 실행이 막히면 `problems.json`의 저장 출력을 보여 주고 "미리 실행한 결과예요"를 띄운다.
4. 실행하는 코드는 `problems.json`에 사람이 넣고 검사를 통과한 코드, 그리고 "바꿔 보기"에서 정해 둔 칸 · 값만 바꾼 코드뿐이다.
5. 저장 출력이 실제 출력과 같은지는 `tools/check_problems.mjs`가 Node의 `vm`(1초 상한)으로 확인한다. 출력 글자 규칙은 브라우저와 검사 도구가 같다([데이터 설계 2-3](../data-model.md)).

## 4. 결과 (Consequences)

### 좋아지는 점
- 끝나지 않는 코드가 있어도 화면이 멈추지 않는다.
- 예제 코드가 화면 · 학습 기록에 손대지 못한다.
- 실행이 막히는 환경에서도 학습이 이어진다.

### 감수하는 점
- ① 해석 보기의 한 줄 실행 장면(변수 상자 · 출력)은 문제를 만들 때 문제 데이터(`trace`)에 미리 적어야 한다. Claude가 초안을 쓰고 사용자가 검토한다(요구 Q13). 검사 도구는 마지막 장면의 출력만 확인한다.
- 일꾼 안에는 화면(DOM)이 없어서, 화면을 바꾸는 예제는 다룰 수 없다. 첫 시제품 범위(출력 비교)에는 문제없다.
- 1초는 추론한 숫자다(요구 AS-2). 시제품 문제를 쓴 뒤 실제 실행 시간을 재서 확인한다.

## 5. 다시 검토할 조건
- 파이썬 · SQL을 더할 때(브라우저용 실행기가 필요하다)
- ① 해석 보기 장면을 자동으로 만들고 싶을 때(해석기 라이브러리 검토, 새 ADR)
- 3D 실행 장면을 붙일 때
