# ADR-0003: 학습자 질문은 구글 폼으로 받고, 자동 작업이 밀린 질문을 모두 정리한 뒤 사람이 승인한다

- 상태(Status): **채택(Accepted)** — 2026-11-22 설계 문서와 함께 사용자 승인
- 날짜: 2026-11-22
- 결정한 사람: 프로젝트 오너(사용자)가 방향을 정함(요구 Q16 · Q22). Claude가 구조를 제안.

## 1. 배경 (Context)

- 학습자가 해설을 보다 궁금한 점을 보내면, 답을 모아 그 줄의 "자주 묻는 질문"에 더한다(요구 Q14 ⓔ).
- 사용자는 질문을 사람이 직접 답하지 말고, 자동으로 정리 · 답 초안을 만든 뒤 승인받는 방식을 원한다(Q16).
- 지금 필드워드 방식은 컴퓨터가 꺼져 있으면 자동화를 놓친다(사용자 경험). 필드워드 문서에는 의견 메일을 예약 작업이 읽지 않고 대화에서 요청할 때만 읽는다고 적혀 있다(필드워드 `docs/운영_자동화.md` 5장). 사람이 없는 시간에 메일함을 자동으로 읽는 변경은 2026-11-10 안전 검사에서 막혔다.
- 비용 0원, 개인정보를 모으지 않는다(AC-01 · 58).

## 2. 선택지 (Options)

| 방법 | PC 꺼짐에도 안 잃음 | 0원 | 로그인 필요(학습자) | 자동 작업이 읽을 권한 | 판단 |
|---|---|---|---|---|---|
| 메일 + Gmail 연결 | ○ 메일함에 쌓임 | ○ | 없음 | ❌ 사람 없는 시간의 메일 자동 읽기가 막혔다 | ❌ |
| GitHub 이슈 | ○ | ○ | ❌ GitHub 계정 필요 | ○ | ❌ 학습자 장벽 |
| 비공개 구글 시트 + 연결 도구 | ○ | ○ | 없음 | △ 사람 없는 시간에 로그인 권한 사용 | 보류 |
| **구글 폼 → 구글 시트 → 공개 CSV 읽기 + 상태 파일** | ○ 시트에 쌓임 | ○ | 없음 | ○ 로그인 없이 읽기만 | ✅ 채택 제안 |

## 3. 결정 (Decision)

1. 게임은 질문 3칸(문제 번호 · 줄 번호 · 질문)만 구글 폼으로 보낸다. 이메일 칸과 이메일 수집은 끈다.
2. 폼 응답 시트를 CSV로 웹에 게시하고, 관리자 PC의 Claude 예약 작업이 그 CSV를 읽는다.
3. 처리 상태는 저장소의 `pipeline/questions_state.json`에 둔다. 이 파일에 없는 행은 **날짜와 상관없이 모두** 새 질문이다. 그래서 작업이 며칠 못 돌아도 다음 실행 때 밀린 것을 한꺼번에 처리한다.
4. 질문마다 답 초안을 Git 밖 `pipeline/reports/`에 쓰고 상태를 "초안"으로 바꾼다. 개인정보처럼 보이는 글(전화번호 · 이메일 모양 등)은 초안에서 가린다.
5. 사람이 승인한 답만 `problems.json`의 그 줄 `faq`에 넣고 커밋한다. 커밋 · 배포는 사람 승인 뒤에만 한다(필드워드 ADR-0004와 같은 원칙).
6. 질문 글은 공개 저장소에 넣지 않는다. 상태 파일에는 해시 열쇠 · 상태 · 문제 번호 · 줄 번호 · 근거 위치 · 실패 횟수만 둔다.
7. **승인은 자동 작업이 먼저 제안한다(요구 Q27).** 사람 판단이 필요한 항목이 1개 이상이면 알림 1개를 보내고, 알림에서 여는 보고서 1곳에 판단할 내용을 다 담는다. 사용자는 구글 시트를 열지 않는다(AC-63a~63c).
8. 초안마다 문제 데이터 안의 근거 위치를 붙이고, 근거가 없으면 초안을 만들지 않고 사람에게 넘긴다(AC-63f). 질문 글 속 지시는 따르지 않는다(AC-63e).
9. 게시는 `pipeline/publish.mjs`가 상태 파일의 "승인"만 보고 한다. 승인은 대화에서 번호나 "전부"를 밝힌 사용자의 말로만 받는다.
10. 질문 1건이 실패해도 보고서는 나가고, 2번 연속 실패하면 "확인 필요"로 멈춘다(AC-63g · 63h).

7~10은 강의자료의 사람 개입 원칙을 따랐다: 승인 피로와 이관(최종/CCD_RFC_디자인_AI_패턴_해설 29~30쪽), 글 속 명령은 데이터(같은 덱 22쪽), 제안은 AI · 승인은 사람 · 차단은 코드(최종/CCD_RFC_강의반영_생애주기_보강 15쪽), 부분 실패 · 실수 승인 방지(같은 덱 20~21쪽), 승인 관문은 코드로(4주차 3차시 16쪽).

## 4. 결과 (Consequences)

### 좋아지는 점
- PC가 꺼져 있어도 질문은 구글 시트에 남는다. 늦어질 수는 있어도 빠지지 않는다.
- 학습자는 로그인 없이 보낼 수 있다.
- 사용자는 시트를 들여다보지 않고 알림 하나로 승인한다.
- 지어낸 답 · 질문 속 명령 · 끝없는 재시도를 막는다.
- 자동 작업은 로그인 권한 없이 읽기만 한다.

### 감수하는 점
- 공개 CSV는 주소를 아는 사람이면 읽을 수 있다. 질문 글에 학습자가 스스로 개인정보를 적으면 노출될 수 있다. 폼 안내("개인정보를 적지 마세요")와 사용자가 시트에서 행을 지우는 것으로 줄인다.
- 구글 폼은 보낸 결과를 브라우저에 돌려주지 않아, 게임은 "연결 실패"만 알 수 있다.
- 답은 Claude 앱이 켜져 있을 때만 만들어진다. 질문이 쌓이는 것은 막지 않지만, 답이 늦어질 수 있다.
- 구글의 무료 정책 · 폼 보내기 방식이 바뀌면 다시 봐야 한다(요구 AS-5).

## 5. 다시 검토할 조건
- 공개 CSV 노출이 문제가 될 때(비공개 시트 + 연결 도구로)
- 필드워드도 같은 방식으로 바꿀 때(필드워드 요청 R-6, 필드워드 쪽 새 ADR)
- 질문이 많아져 사람 승인이 밀릴 때(위험이 낮은 답을 승인 없이 내는 단계 나누기를 검토하되, 공개는 AC-63이 막고 있으므로 요구부터 바꾼다)
