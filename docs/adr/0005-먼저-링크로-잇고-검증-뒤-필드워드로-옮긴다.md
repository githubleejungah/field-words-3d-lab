# ADR-0005: 게임은 먼저 링크로 필드워드에 잇고, 검증 뒤 필드워드 저장소로 옮긴다

- 상태(Status): **채택(Accepted)** — 2026-11-23 초안, 2026-11-24 빠진 6가지를 더해 사용자 승인("승인", "네, 그렇게 해주세요")
- 날짜: 2026-11-23
- 결정한 사람: 프로젝트 오너(사용자)가 방향을 정함("필드워드에서 게임을 계속 발전시키는 방안은요?", "우선 1을 하고"). Claude가 선택지를 비교하고 추천.
- 대체하는 것: 없음. [ADR-0001](0001-필드워드-밖-별도-저장소에서-시작.md) 3장 4번 "시제품이 검증되면 필드워드에 붙이기 위한 ADR 초안을 넘긴다"를 구체화한다.

## 1. 배경 (Context)

- 게임 시제품의 기능은 거의 다 만들었다. 문제 8개, 사다리 ①②③, 복습 · 등급, 배치 시험, 실전 읽기 확인이 있고, 수용 기준은 102개, 단위 시험 73개가 통과한다. 질문 보내기(`ask.js`)는 구글 폼을 만든 뒤에 만든다.
- 성공 지표(AC-76: 4주차 착각 비율이 1주차보다 낮음)는 아직 재지 않았다. 4주 사용이 필요하다.
- 지금 기획 · 개발하는 Claude 계정은 강의가 끝나는 2026-11-28 뒤에는 쓸 수 없다(ADR-0001). 이 날짜는 늘어날 수 있다. 그 뒤에는 필드워드를 맡은 다른 계정이 이어 가야 한다.
- 필드워드 관찰(커밋 `b93119b`, 2026-11-23):
  - 필드워드에도 `site/js/app.js` · `review.js`가 있어 게임 파일 이름과 겹친다.
  - 필드워드 ADR이 0001~0005까지 있어 번호가 겹친다.
  - 필드워드는 GitHub Actions(`.github/workflows/pages.yml`)로 `site/`를 배포한다.
  - 배포된 용어 사전 주소는 `https://githubleejungah.github.io/field-words/data/glossary.json`이다(응답 200 확인). 게임이 처음 찾는 주소와 같다.
- **이어받기 전제**: 필드워드 계정도 같은 PC와 같은 GitHub 사용자(`githubleejungah`)로 일한다. 그래서 이 폴더와 비공개 저장소에 들어올 수 있다. 이 전제가 틀리면 3장 3번이 성립하지 않는다(5장).
- 공개 전 점검을 한 번 돌려 보았다(2026-11-23, 지난 커밋 전체): 이메일 3종이 나왔다. README 연락처(일부러 공개), 시험용 `example.com`(예시 주소), 요청 목록 O-14의 메일 주소(필드워드 공개 사이트에도 이미 있음, 사용자 판단 필요). 커밋 작성자 이메일은 모두 GitHub `noreply` 주소다.
- 두 사이트가 같은 주소(`githubleejungah.github.io`) 아래에 있으면 브라우저 저장소를 함께 쓴다. 게임 기록(`cm:v1:*`)과 필드워드 기록(`fw:v1:*`)은 앞글자가 달라 섞이지 않는다(data-model 4장).

## 2. 선택지 (Options)

| 방법 | 지금 할 일 | 필드워드에서 고칠 것 | 계정이 바뀐 뒤 | 판단 |
|---|---|---|---|---|
| A. 링크로만 잇기 | 게임 따로 배포 | 메뉴에 링크 1개 | 누가 개발할지 정해지지 않음 | △ 개발을 이어 갈 길이 빠짐 |
| B1. 저장소는 따로, 필드워드 계정이 이 폴더를 이어받기 | 넘김 문서 | 없음 | 필드워드 계정이 이 폴더에서 개발 | △ 저장소 · 배포가 계속 2개 |
| B2. 지금 바로 필드워드 저장소로 옮기기 | 파일 · 문서 · 검사 도구 · 시험을 옮기고 합치기 | 많음(하위 폴더, 문서 합치기, ADR 번호) | 필드워드 저장소에서 개발 | ❌ 11-28 전에 끝내기 빠듯. 검증 전이라 아직 많이 바뀌는데 필드워드 승인 절차에 묶임. 두 계정이 같은 저장소를 동시에 고쳐 ADR-0001이 피하려던 충돌이 생김 |
| C. 필드워드 `app.js`에 섞기 | 화면 · 기록 형식 합치기 | 매우 많음 | — | ❌ 일이 크고, 기록 형식까지 바뀜 |
| **단계별: 지금 A + B1, 검증 뒤 B2** | 링크 배포 + 넘김 문서 | 지금은 링크 1개 | 검증 전엔 이 폴더, 검증 뒤 필드워드 저장소 | ✅ 채택 제안 |

## 3. 결정 (Decision)

1. **지금은 링크로 잇는다.** 게임 저장소를 공개로 바꾸고, GitHub Actions로 `site/`를 `https://githubleejungah.github.io/field-words-3d-lab/`에 배포한다(비용 0원, AC-01 · A13).
   - **공개 전환은 사용자 승인 뒤에만 한다.** 공개는 되돌리기 어렵다(복제 · 캐시가 남음). 공개 점검 도구의 보고서를 사용자가 보고 승인한 뒤 바꾼다.
   - **찾기는 도구, 결정은 사람, 막기는 배포 관문**: 공개 점검 도구(`tools/check_public.mjs`)가 지금 파일 · 지난 커밋 전체 · 커밋 작성자 이메일에서 비밀 값 모양을 찾아 허용 목록(`tools/public_allow.json`)에 없는 것을 보고하고 처리 방법을 제안한다(AC-86). 도구는 파일과 기록을 고치지 않는다(AC-87). 배포 작업은 이 도구를 먼저 돌리고, 허용되지 않은 것이 1개라도 있으면 배포하지 않는다(AC-88).
2. **필드워드에는 메뉴 링크 1개만 요청한다**(요청 목록 R-8). 이 저장소는 필드워드 저장소를 고치지 않는다(ADR-0001 그대로). **필드워드가 링크를 미루거나 달지 않아도 게임은 자기 주소에서 그대로 동작한다.** 링크를 기다리느라 다른 일을 멈추지 않는다.
3. **이 계정을 쓸 수 없게 되면, 필드워드 계정이 이 폴더를 이어받아 개발한다**(B1). 이어받는 방법은 넘김 문서에 적는다. **질문 자동 정리 예약 작업(`pipeline/`)도 함께 넘긴다.** 예약 작업이 남지 않으면 질문이 쌓이기만 하고 처리되지 않기 때문이다.
4. **옮기는 조건**: 아래 두 가지가 모두 되면 필드워드 저장소로 옮긴다(B2). 옮기는 방법(하위 폴더 이름, 문서 합치기, 검사 도구 위치)은 그때 새 ADR로 정한다.
   - 4주 사용 뒤 4주차 착각 비율이 1주차보다 낮다(AC-76, 사용자 1명 기준).
   - 사용자가 옮기기를 승인한다.
5. **끝나는 조건**: 4주 뒤 착각 비율이 낮아지지 않으면 옮기지 않는다. 그때 사용자에게 "고쳐서 4주 더 재기 · 링크로 유지 · 멈추기" 중 하나를 묻는다. 묻지 않고 재기를 끝없이 늘리지 않는다.
6. **학습 기록은 끊기지 않게 한다.** 옮길 곳도 같은 주소(`githubleejungah.github.io`) 아래로 하고, 기록 키 `cm:v1:*`는 바꾸지 않는다.
7. **기능을 늘릴 때(범위 확장)의 규칙**: 이어받은 뒤에도 이 저장소 순서를 지킨다(요구 → 수용 기준 → 설계 → 사용자 승인 → 코드, CLAUDE.md).
   - **검증 시작일은 사용자가 정한다**(추천: 공개 배포한 날). 그 전에는 기능을 더할 수 있다.
   - **검증 4주 동안은 버그 수정만 한다.** 문제 · 단계 · 규칙 숫자를 바꾸지 않는다. 1주차와 4주차를 같은 조건에서 비교해야 성공 지표(AC-76)를 믿을 수 있기 때문이다.
   - 요구 문서에서 범위 밖으로 정한 것을 넣으려면 새 ADR을 쓴다. 3D 화면은 이미 정한 대로 다음 단계에서 2D 화면과 함께 둔다(AC-72 · 73).

## 4. 결과 (Consequences)

### 좋아지는 점
- 필드워드는 링크 1개만 바꾸면 되어, 다른 계정 작업과 충돌하지 않는다.
- 계정이 바뀌어도 개발이 끊기지 않는다(이 폴더 + 넘김 문서).
- 옮기는 작업을 검증 뒤 한 번만 한다. 모양이 굳은 뒤라 두 번 일하지 않는다.
- 어느 단계에서도 학습자 기록이 이어진다.

### 감수하는 점
- 검증이 끝날 때까지 저장소 · 배포 · 문서 체계가 2개다.
- 저장소를 공개로 바꾸면 지난 커밋까지 모두 보인다. 그래서 공개 전 점검이 꼭 필요하다(예: 요청 목록의 이메일 주소는 지난 커밋에도 남아 있다).
- 두 사이트의 디자인 토큰(색 · 간격)은 사본이라, 필드워드가 바뀌어도 자동으로 따라가지 않는다(data-model 1장). 옮길 때 맞춘다.

## 5. 다시 검토할 조건

- 4주 검증 결과가 나왔을 때(옮기기 · 유지 · 멈추기 결정, 새 ADR)
- 필드워드를 맡는 계정이 하나로 합쳐질 때
- 필드워드 용어 사전 주소나 배포 방식이 바뀔 때
- 이 계정을 쓸 수 있는 날이 늘어나 B2를 서두를 이유가 없어졌거나, 반대로 앞당겨졌을 때
- 이어받기 전제(같은 PC · 같은 GitHub 사용자)가 틀렸을 때
- 공개 점검에서 지난 기록까지 지워야 하는 것이 나왔을 때(기록 다시 쓰기 또는 기록 없이 새 공개 저장소 시작을 새로 정함)
