## 1. 정본 표

**정본(正本, Source of Truth)**은 값이 둘로 갈라지면 "이쪽이 맞다"고 정한 원본입니다. **주인(Owner)**은 정본을 바꿀 수 있는 사람이나 프로그램입니다. **사본(Copy)**은 정본에서 만든 것이라, 고칠 때는 사본이 아니라 정본을 고칩니다.

| 데이터 | 정본 (어디에) | 주인 (누가 바꾸나) | 사본 · 파생 |
|---|---|---|---|
| 문제 데이터 (코드 · 가릴 줄 · 보기 · 풀이 · 이름표 · 우리말 코드 · 선행 문제 · 저장 출력) | `site/data/problems.json` (Git) | 개발자. Claude가 초안을 쓰고 사람이 검토한 뒤 `check_problems.mjs` 통과 시 커밋 | 배포된 Pages의 같은 파일, 브라우저 메모리 |
| 문제 등급 `level` | **파생값**. 정본은 "용어 등급(필드워드)"과 "코드 난이도 `code_level`" | — | `problems.json`의 `level`은 사본. 검사 도구가 max(용어 등급, 코드 난이도)와 같은지 확인한다(AC-09) |
| 저장 출력 `outputs` | **파생값**. 정본은 코드 자체 | — | `problems.json`에 사본으로 둔다(실행이 막힐 때 대체용, AC-64). 검사 도구가 실제 실행 결과와 같은지 확인한다 |
| 자주 묻는 질문 · 답 (`faq`) | `site/data/problems.json` (Git) | 개발자. 질문에서 온 답은 사용자가 승인한 것만 | — |
| 코드 낱말 뜻 | `site/data/words.json` (Git) | 개발자 | — |
| 실전 읽기 코드 · 모범 답 · 꼭 짚을 점 | `site/data/reading.json` (Git) | 개발자. Claude가 사용자 프로젝트(리테일 챗봇)에서 골라 초안을 쓰고, **사용자가 비밀 값이 없는지 본 뒤** 검사 도구 통과 시 커밋(AC-85) | 원본 코드는 사용자 비공개 저장소가 정본. 이 파일은 20~30줄 사본이고 `source`에 출처를 적는다 |
| 용어 · 용어 등급 · 비유 | 필드워드 `site/data/glossary.json` (필드워드 저장소) | 필드워드 계정. **이 저장소는 고치지 않는다** | 게임은 배포된 파일을 읽기만 한다(메모리) |

| 학습자 코드 등급 | **반쯤 파생값**. 계산 근거는 학습 기록 | `grade.js` | 내려가지 않게 "지금까지 오른 가장 높은 등급"만 `cm:v1:grade`에 저장한다(AC-40) |

| 디자인 토큰 (색 · 간격) | `site/css/style.css` | 개발자 | 필드워드 `style.css`에서 옮겨 온 값. 필드워드가 바뀌어도 자동으로 따라가지 않는다 |

- 서버가 없으므로 학습 기록의 정본은 학습자 기기에만 있습니다. 관리자는 누가 무엇을 틀리는지 모릅니다. 성공 지표(AC-76)는 사용자 본인의 기록으로 봅니다.

## 2. 문제 데이터 `problems.json`

### 2-1. 한눈에 보기

```
problems.json
├── schema_version   "1.0"
├── updated_at       "2026-11-22"
└── problems[]
    ├── id            "cache-basic"        ← 바꾸지 않는 이름표 (학습 기록이 이 id로 저장된다)
    ├── lang          "javascript"          ← 언어 칸 (AC-06)
    ├── terms[]       ["cache"]             ← 필드워드 용어 id, 1개 이상 (AC-07)
    ├── code_level    3                     ← 코드 난이도 1~4 (A10 기준표)
    ├── level         3                     ← 사본: max(용어 등급, code_level) (AC-09)
    ├── prereq[]      ["assign-basic"]      ← 선행 문제 id, 없으면 [] (AC-36)
    ├── code[]        9줄                   ← 3~10줄, 한 줄에 동작 1개 (AC-08)
    ├── explain[]     9줄                   ← 줄마다 우리말 풀이 (① 해석 보기)
    ├── ko[]          9줄                   ← 줄마다 우리말 코드 (AC-53)
    ├── pieces[][]    [[코드 조각, 뜻], …]   ← 줄마다 조각 풀이 (① 지금 줄 칸)
    ├── names         { "codeOk": "인증 번호 맞음?" }  ← 변수 이름 풀이 (변수 상자)
    ├── labels[]      [{ from, to, text }]  ← 덩어리 이름표 (AC-55)
    ├── in_code[]     [{ text, lines[] }]   ← 이 코드 속 용어: 비유의 각 부분 = 코드 몇 번 줄 (1~4개)
    ├── trace[]       [{ line, vars, out, note }]   ← ① 다음 줄 실행 장면
    ├── words[]       ["const", "if", ...]  ← 누를 수 있는 낱말 (words.json 키)
    ├── outputs       { original: [...] }   ← 저장 출력 사본
    ├── masks[2]                            ← 가릴 줄 후보 2개 (AC-10)
    │   ├── line      4                     ← 0부터 센 줄 번호
    │   ├── output    [...]                 ← 이 줄을 가렸을 때 저장 출력 사본
    │   ├── predict   { options[4] }        ← ② 예측 보기 (AC-12)
    │   └── interpret { options[4] }        ← ③ 해석 보기 (AC-12)
    │       └── options[] { text, correct, why, out?, code? }   ← 틀린 보기의 why = 착각 풀이 (AC-13)
    │                       out: ② 보기의 출력 줄, code: ③ 보기의 코드 조각
    ├── faq           { "4": [ { q, a, from } ] }  ← 줄 번호별 자주 묻는 질문 (AC-49)
    └── play?         { slots[], fixed_outputs? }  ← 바꿔 보기, 있을 때만 (AC-52)
        └── slots[]   { name, line, token, values[] }
```

`?`가 붙은 칸은 선택 칸입니다. 없으면 칸 자체를 뺍니다.

### 2-2. 칸 규칙

| 칸 | 규칙 | 검사 (`check_problems.mjs`) |
|---|---|---|
| `id` | 영어 소문자 · 숫자 · 하이픈. 한 번 정하면 바꾸지 않는다 | 형식, 겹침 없음 |
| `code` | 3~10줄. 한 줄에 동작 1개(여러 동작을 한 줄에 몰지 않는다, Q25) | 줄 수. "한 줄에 동작 1개"는 사람 검토 |
| `code`의 비동기 | `async` · `await` · `Promise`는 쓸 수 있다. **타이머(`setTimeout` · `setInterval`)는 쓰지 않는다.** 기다리는 시간이 1초 상한(AC-67)과 부딪히고, 타이머 순서는 브라우저와 검사 도구에서 같다고 보장하기 어렵기 때문이다(2026-11-22 결정, 2026-11-23 문서에 적음) | 검사 도구의 실행 환경에는 타이머가 없어서, 쓰면 실행 중 오류로 걸린다(`run-original`) |
| `explain` · `ko` | `code`와 줄 수가 같다 | 줄 수 같음 |
| `labels` | 겹치지 않고 `code` 줄 범위 안. ①에서만 보인다(AC-56) | 범위 · 겹침 |
| `in_code` | 1~4개 항목. 항목마다 글(`text`, 예: "도어락 = 인증 번호 확인")과 줄 번호(`lines`, 0부터) 1개 이상. 용어가 코드의 낱말 하나가 아니라 흐름일 때도, 그 흐름이 몇 번 줄인지 보이게 한다. ①과 답한 뒤에만 보인다(2026-11-22 결정) | 개수 · 줄 범위 |
| `masks` | 정확히 2개, 서로 다른 줄. 지워도 문법 오류 0건, 원래 출력과 1곳 이상 다름(AC-11). 실행 중 오류 · 1초 넘김도 0건(브라우저가 출력 대신 오류를 보여 주게 되므로) | 두 코드를 예제마다 따로 띄운 일꾼(worker thread) 안에서 `vm`으로 1초 상한 실행해 확인. 비동기 코드 안의 오류도 실행 중 오류로 잡는다 |
| `options` | 정확히 4개, `correct`는 1개. 틀린 보기 3개 모두 `why` 있음 | 개수 · 정답 1개 · why |
| `outputs` · `masks[].output` | 실제 실행 결과와 같다 | 실행 결과와 비교 |
| `trace` | 마지막 장면의 `out`이 `outputs.original`과 같다 | 비교 |
| `level` | max(용어 등급, `code_level`) | 필드워드 데이터로 계산해 비교 |
| `prereq` | 있는 문제 id, 고리(A → B → A) 없음 | 참조 · 고리 검사 |
| `terms` | 필드워드에 있는 용어 id | 참조 검사 |
| `play.slots` | 바꿀 줄 · 바꿀 글자(`token`)와 고를 값 목록. `token`은 그 줄에 정확히 1번. 값은 20자 이하의 숫자 · 한글 · 영문 · 띄어쓰기 · `._-`만(코드 조각 금지) | 값마다 실행해 오류 없이 1초 안에 끝나는지 |
| `words` | `words.json`에 있는 낱말만 | 참조 검사 |
| `pieces` | `code`와 줄 수가 같다. 줄마다 [코드 조각, 뜻] 1개 이상. 조각은 그 줄 안에 차례대로 들어 있다(띄어쓰기 · 괄호 · `;`는 빼도 됨). 초보가 기호(`!` = 아니다)와 이름을 짐작으로 읽지 않게 한다(2026-11-22 결정) | 줄 수 · 차례 |
| `names` | 코드에 실제로 있는 이름만. 뜻은 짧게("인증 번호 맞음?") | 이름이 코드에 있는지 |
| `predict.options[].out` | ② 보기를 실제 출력 모양으로 보여 줄 출력 줄(4줄 이하). 가린 코드의 출력이 4줄 이하면 정답 보기에 반드시 있고, 실제 실행 결과와 같아야 한다. 4줄을 넘으면 짧은 설명 글(`text`)로 둔다. "에러가 난다"처럼 출력이 아닌 보기는 `out` 없이 글로 둔다 | 정답 = 실제 출력 |
| `interpret.options[].code` | ③ 보기마다 그 보기가 가리키는 코드 조각. 정답은 가린 줄 안의 조각, 틀린 보기는 잘못 읽은 코드(예: `!`를 빼고 읽은 `if (codeOk)`) | 모두 있음 · 정답은 가린 줄 안 |
| `faq` | 열쇠는 0부터 센 줄 번호(설계 결정 3), 항목마다 `q` · `a` | 범위 · 칸 |

### 2-3. 출력 글자 규칙

`console.log`의 값이 여러 개면 띄어쓰기 하나로 잇습니다. 글자는 그대로, 그 밖의 값(숫자 · 배열 · 객체)은 `JSON.stringify`로 바꿉니다. 브라우저 실행기와 검사 도구가 같은 규칙을 써야 저장 출력과 실제 출력이 같아집니다.

### 2-4. 예시 (시안의 캐시 문제, 일부)

### 2-5. 문제 목록 (AC-74: 검증 시작 전 24개, 등급마다 6개)

처음 8개(2026-11-22)에 16개를 더한다(2026-11-24, Q33). 28일 모의 실험에서 8개면 4주차 답이 거의 없어 성공 지표를 판단하지 못했기 때문이다.

| 등급 | 문제 (`id`) | 다루는 동작 | 필드워드 용어(용어 등급) | 가릴 줄 후보(화면 번호) |
|---|---|---|---|---|
| 1 입문 | 값 넣기 (`assign-basic`) | `=`로 값 넣기 | `backup` 백업(1) | 2 · 3 |
| 1 입문 | 값 합치기 (`concat-basic`) | 글자 · 숫자 잇기, 왼쪽부터 계산 | `saas` 서비스형 소프트웨어(1) | 2 · 3 |
| 2 기본 | 조건 (`if-basic`) | `if` · `!` · `&&`, 문 두 개(비밀번호 · 인증 번호) 확인 | `mfa` 다중 인증(1) → 문제 등급 2 | 5 · 7 |
| 2 기본 | 반복 (`loop-basic`) | `for ... of`, 개수 세기 | `batch-processing` 배치 처리(2) | 4 · 5 |
| 3 실무 | 캐시 (`cache-basic`) | 함수 · 객체 | `cache` 캐시(2) → 문제 등급 3 | 3 · 5 |
| 3 실무 | JSON 읽기 (`json-basic`) | `JSON.parse` · `JSON.stringify` | `json` 제이슨(2) → 문제 등급 3 | 4 · 7 |
| 4 심화 | 기다리기 (`poll-basic`) | `async` · `await`, 기다리는 동안 다음 줄 | `polling` 폴링(3) → 문제 등급 4 | 6 · 9 |
| 4 심화 | 재시도 (`retry-basic`) | `for await`, 기다림 두 배로 늘리기 | `retry` 재시도(2) → 문제 등급 4 | 6 · 7 |

- 8문제 모두 만들었습니다(2026-11-22). 용어와 용어 등급은 필드워드 `glossary.json`에서 확인했고, 문제 등급은 max(용어 등급, 코드 난이도)입니다(AC-09).

## 4. 학습 기록 `localStorage` (`cm:v1:*`)

`cm`은 **c**ode **m**ask(코드 가려 보기), `fw`는 **f**ield **w**ords(필드워드), `v1`은 저장 형식 1판(version 1)의 앞글자다. 필드워드(`fw:v1:*`)와 앞글자를 다르게 해서 섞이지 않게 합니다. 게임은 `fw:v1:*`를 읽지도 쓰지도 않습니다.

| 키 | 모양 | 설명 |
|---|---|---|
| `cm:v1:problem:<문제 id>` | `{ box, status, next_stage, mask_next, reviews, first_at, last_at, next_review_at, history[], mis?, priority_day? }` | 문제별 복습 기록. `next_stage`는 다음 판의 시작 단계(1 · 2 · 3). `mask_next`는 다음에 가릴 후보 번호(0 · 1). `reviews`는 복습 판 수(처음 만난 판은 세지 않음, 0이면 첫 복습). `last_at`은 마지막으로 상자를 옮긴 날(하루 첫 답). `priority_day`는 "나중에 다시"로 1순위가 된 날, 풀면 지운다(AC-28) |
| ↳ `mis` | `{ line, streak, last_day }` | 착각 표시. 있으면 착각 중. `streak`은 서로 다른 날 연속 "확실해요 + 맞음" 횟수, 2가 되면 `mis`를 지운다(AC-29). `last_day`는 착각한 날 · 센 날 · 틀린 날 중 마지막 날이고, 이날보다 뒤의 날만 센다 |
| ↳ `history[]` | `{ at, step, mask, confidence, correct, status, retry? }` 최근 20개 | 필드워드와 같은 개수(`HISTORY_KEEP` 20). `retry`는 착각 다시 풀기 답 |
| `cm:v1:today` | `{ date, steps_done, new_steps_done, seen[], extra }` | 오늘 한 단계 수, 그중 새 문제에 쓴 단계 수(새 문제 몫 30% 계산, AC-34), 오늘 본 문제 id(다시 넣지 않음), "더 하기"로 늘린 단계 수(5단계씩, 필드워드와 같음). 날짜가 바뀌면 새로 시작 |
| `cm:v1:log` | `{ "2026-11-22": { answers, misconceptions } }` | 날짜별 답 수 · 착각 수. 주간 착각 비율 계산용(AC-75). 착각 다시 풀기 답은 넣지 않는다 |
| `cm:v1:placement` | `{ done, skipped, start_level, passed_levels[] }` | 배치 시험 결과(AC-46~47c). `passed_levels`는 실제로 맞힌 등급만 담고, 선행 문제 판단(AC-36a)에 쓴다 |
| `cm:v1:grade` | `{ level, milestones_shown }` | 지금까지 오른 가장 높은 등급, 지금 등급에서 이미 보여 준 이정표 수. 처음 값은 배치 시험의 시작 등급. 승급하면 새 등급에서 이미 지난 이정표는 보여 준 것으로 친다(배너는 1개, AC-44) |
| `cm:v1:settings` | `{ daily_goal: 10, min_goal: 3 }` | 하루 목표(AC-33) |
| `cm:v1:validation` | `{ start, history: [ { start, end, week1: { answers, misconceptions }, week4: { answers, misconceptions } } ] }` | 4주 변화 재기(AC-89~94). `start`는 검증 시작일(없으면 키가 없음). `end`는 시작일 + 27일(4주의 마지막 날). "다시 재기" 때 지난 결과를 `history`에 1개 남긴다. 주간 착각 비율은 `cm:v1:log`에서 매번 계산하고 여기에는 끝난 결과만 둔다 |
| `cm:v1:outbox` | `[ { problem_id, line, question, saved_at, tried } ]` | 못 보낸 질문. `tried`가 1이면 더 보내지 않고 안내만(AC-68) |
| `cm:v1:reading` | `{ runs: [ { reading_id, day, answers: { what, io, key }, marks[], score, repeat } ] }` | 실전 읽기 회차 기록(7장). `plan.js` · `grade.js` · `review.js`는 이 키를 읽지 않는다(AC-84) |

### 4-1. 복습 상자 (필드워드와 같은 숫자, AC-32)

## 5. 질문 데이터

### 5-1. 구글 폼 칸 (3칸, AC-57)

| 칸 | 예 | 비고 |
|---|---|---|
| 문제 번호 | `cache-basic` | 게임이 채운다 |
| 줄 번호 | `3` | 게임이 채운다(사람이 읽는 1부터) |
| 질문 | "이 줄은 모양을 만드는 줄인가요?" | 학습자가 쓴다. 폼 안내: "이름 · 연락처 같은 개인정보는 적지 마세요" |

- 이메일 칸은 만들지 않습니다(AC-58). 구글 폼의 "이메일 수집" 설정도 끕니다.
- 시트에는 구글이 붙이는 제출 시각이 함께 쌓입니다.

### 5-2. 처리 상태 `pipeline/questions_state.json`

```
{ "rows": { "<제출 시각 + 질문 앞 20자의 해시>": { "status": "초안", "problem_id": "cache-basic", "line": 3, "draft": "질문초안_2026-11-23.md", "evidence": ["explain:3", "words:return"], "fail_count": 0, "decided_at"?: "..." } } }
```

- 상태: 새 질문(이 파일에 없음) → 초안 | 근거 없음 | 확인 필요 → 승인 | 보류 → 게시.
  - 초안: 근거 위치(`evidence`) 1곳 이상이 있는 답 초안(AC-63c).
  - 근거 없음: 문제 데이터에서 근거를 못 찾음. 초안을 만들지 않는다(AC-63f).
  - 확인 필요: 초안 만들기가 2번 연속 실패(`fail_count` = 2). 더 시도하지 않는다(AC-63h).
  - 초안 · 근거 없음 · 확인 필요는 모두 "사람 판단이 필요한 항목"이라 승인 요청 알림에 오른다(AC-63a).
  - "고쳐 줘"는 초안으로 되돌린다. 보류는 다시 제안하지 않는다(AC-63d).
- `evidence` 칸은 근거가 있는 곳의 이름만 적는다(`explain:줄`, `faq:줄`, `words:낱말`, `glossary:용어`). 질문 글은 담지 않는다.
- 질문 글은 넣지 않습니다. 저장소가 공개라서 글은 시트와 Git 밖 초안에만 둡니다.
- 열쇠를 "해시(Hash: 글을 짧은 고유 문자열로 바꾼 값)"로 만들어, 같은 행을 두 번 처리하지 않습니다.

## 6. 설계 결정

| # | 결정 | 이유 |
|---|---|---|
| 1 | 문제 `id`는 바꾸지 않는 슬러그 | 학습 기록이 이 id로 저장된다. 바뀌면 기록이 끊긴다 |
| 2 | `level` · `outputs`는 사본으로 두고 검사 도구가 맞는지 확인 | 실행 시 필드워드 데이터나 실행기가 없어도 문제를 낼 수 있게(대체하고 계속, Q19) |
| 3 | 줄 번호는 데이터에서 0부터, 화면 · 질문 폼에서는 1부터 | 코드 배열과 맞추고, 사람에게는 익숙한 번호로 |
| 4 | 등급은 "가장 높이 오른 값"만 저장 | 계산값만 쓰면 상자가 내려갈 때 등급도 내려간다. 강등 없음(AC-40) |
| 5 | 질문 상태는 Git의 상태 파일, 질문 글은 시트에만 | 시트에 쓸 권한 없이(공개 CSV 읽기만으로) 처리하고, 공개 저장소에 질문 글을 올리지 않기 위해 |

| 7 | 게시는 `publish.mjs`가 상태 파일의 "승인"만 보고 한다 | 승인 관문을 프롬프트가 아니라 코드로 강제하기 위해(Q27, 강의 4주차 3차시 16쪽) |
| 8 | 실전 읽기는 문제 데이터와 다른 파일 · 다른 기록 키에 둔다 | 재는 것과 연습하는 것을 섞지 않기 위해(AC-84). 복습 상자 · 등급 코드가 실수로 읽을 길을 없앤다 |

## 7. 실전 읽기 데이터 `reading.json`

### 7-1. 한눈에 보기

```
reading.json
├── version: 1
└── readings[]
    ├── id: "chat-input"                 ← 바꾸지 않는 슬러그(기록이 이 id로 저장됨)
    ├── lang: "typescript"                ← 화면 위에 언어 이름만 보여 준다
    ├── source: { repo, path, from, to, commit }   ← 출처(사람 확인용, 화면에 안 보임)
    ├── code: ["...", ...]                ← 20~30줄(AC-79). 실행하지 않는다
    ├── model: { what, io, key: { line, why } }    ← 3칸 모범 답(AC-81 · 82). line은 0부터
    └── points: ["...", ...]              ← 꼭 짚을 점 3~5개(AC-82)
```

- 화면에는 제목을 보여 주지 않습니다. 제목이 "무엇을 하나"의 답을 알려 주기 때문입니다.
- 꼭 짚을 점은 "맞힘 · 부분 · 놓침"을 스스로 가리기 쉽게, 한 점에 사실 하나만 씁니다. 예: "입력이 비어 있으면 보내지 않는다(5번 줄)".
- 첫 코드는 리테일 챗봇의 화면 코드(Vue + 타입스크립트)입니다(Q28 ⑥).
- 시제품은 코드 2개로 시작합니다(기준값 1번 + 4주 뒤 1번). 2개는 추론이라 확인할 것에 올립니다(AS-13).

### 7-2. 칸 규칙 (검사 도구가 확인)

| 규칙 | 검사 이름 | 수용 기준 |
|---|---|---|
| `id`가 있고 겹치지 않는다 | `reading-id` | — |
| `code`가 20~30줄 | `reading-lines` | AC-79 · AS-10 |
| `model`의 3칸이 모두 비어 있지 않다 | `reading-model` | AC-81 |
| `model.key.line`이 코드 줄 범위 안 | `reading-key-line` | AC-81 |
| `points`가 3~5개 | `reading-points` | AC-82 · AS-12 |
| 코드 · 모범 답 · 점에 비밀 값 모양이 0개 | `reading-secret` | AC-85 |

- 비밀 값 모양: API 키 · 토큰(`sk-`, `AKIA`, `ghp_`, `AIza`로 시작하는 긴 글자, JWT `eyJ…`), 개인 키 머리글(`-----BEGIN … PRIVATE KEY-----`), `password` · `secret` · `token` · `apiKey`에 따옴표 값을 넣는 줄, 이메일 주소, 휴대폰 번호, 주민등록번호 모양, 아이디 · 비밀번호가 든 연결 주소(`://아이디:비번@`), 사설 IP 주소.
- 모양 검사는 그물일 뿐 다 잡지는 못합니다. **커밋 전 사용자가 직접 보는 것이 첫 관문**이고, 검사 도구는 두 번째 관문입니다.

### 7-3. 기록 `cm:v1:reading`

```
{ "runs": [ { "reading_id": "chat-input", "day": "2026-11-24",
              "answers": { "what": "...", "io": "...", "key": "..." },
              "marks": [1, 0.5, 0, 1], "score": 0.63, "repeat": false } ] }
```

- `marks`: 꼭 짚을 점 순서대로 맞힘 1 · 부분 0.5 · 놓침 0(AC-82 · 83).
- `score` = `marks` 합 ÷ 점 수, 소수 둘째 자리(위 예: 2.5 ÷ 4 = 0.625 → 0.63). 화면에는 백분율(63%)로 보여 줍니다.
- `repeat`: 이미 읽은 코드를 다시 읽은 회차면 `true`. 화면에서 "다시 읽음"을 붙여, 처음 읽은 회차와 구별합니다.
- 회차 수에 상한은 두지 않습니다. 4주에 1번이라 쌓여도 작습니다.
